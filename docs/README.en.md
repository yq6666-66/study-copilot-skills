# Study Copilot

> A universal learning-cognition engine for any AI agent — any host × any subject, with a ready-made postgraduate-exam (考研) subject pack.

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](../LICENSE) [![CI](https://github.com/yq6666-66/study-copilot-skills/actions/workflows/ci.yml/badge.svg)](https://github.com/yq6666-66/study-copilot-skills/actions/workflows/ci.yml) [中文](../README.md)

**Study Copilot** is a pure-Skills learning engine with zero backend services. Install it into an AI agent (Codex, Claude Code, …) and the agent gains cross-session learning memory, error-loop coaching, spaced repetition, study planning, progress diagnosis and original mock exams.

This project is the generalized successor of the author's earlier exam plugin ([kaoyan-408 v2.4.0](https://github.com/yq6666-66/408-codex-plugin)), with two layers of generalization:

1. **Any agent** — Skills are host-decoupled; an adapter layer + installer places the same pack into different hosts.
2. **Any subject** — the mechanism layer treats `subject` as a free string; subject content is driven by declarative packs under `subjects/` (考研 pack preloaded; new subjects generated by the onboarding wizard).

## What it does

### Error loop

- Clusters error causes across questions, strictly separating **confirmed** from **hypothesis** status; hypothesis causes never gate mastery.
- Schedules spaced retests with the open-source [FSRS](https://github.com/open-spaced-repetition/fsrs4anki) core (forgetting curve / initial stability / mean-reversion damping) — suggested review date + today's retrievability per item.
- "Mastered" is gated behind delayed evidence: a pass today must survive a later re-test.
- Never invents causes; anything you didn't state is stored as a hypothesis awaiting confirmation.

### Planning & execution

- Back-plans stage / month / week quotas from your target exam date, resolving cross-subject conflicts.
- Expands "what this week requires" into immediately actionable timeboxes.

### Progress diagnosis & original mock exams

- Diagnoses deviation and risk from recorded data only — never fabricated.
- Runs original mock exams with frozen papers; no hints before submission; results flow back into the error loop.

### Subject tutoring & past-paper workflow

- Per-subject coaches (408 / math / English / politics): concepts, single-question reviews ("point out only my first mistake"), targeted drills.
- Past-paper searcher (license-checked sources, dedup) + analyst (for verified samples only).
- Material assistant turns your own lecture notes into summaries, cards, outlines or original practice.
- Official-info researcher verifies current-year admission data with source and freshness labels.

### On-device semantic retrieval (local AI PC, data stays local)

A bge-small-zh-v1.5 embedding model (ONNX, CPU) indexes error queues and notes locally; similar past mistakes are recalled in milliseconds. The npz vector cache + incremental indexing rebuild a 1%-changed 2,000-doc corpus in 0.39s instead of 7.3s (19×). If the model is unavailable, retrieval degrades to keyword matching — nothing breaks.

```bash
python scripts/local_retrieval/embed_index.py        # build index (auto-downloads model; --fake for offline smoke)
python scripts/local_retrieval/semantic_search.py --query "banker's algorithm deadlock again" --top-k 5
python scripts/local_retrieval/embed_index.py --incremental   # re-encode changed docs only
```

### Cloud variant-question coaching (optional · any OpenAI-compatible model service)

Once the cloud model environment variables are set, the agent can generate **variant questions and second-pass explanations** from confirmed error causes (never copying the original wording), and onboard new subjects (law exam, CPA, anything) as config packs. **Without configuration everything works offline** — only the cloud-specific step degrades, and it says so instead of faking output.

```bash
python scripts/demo_pipeline.py --item r028             # edge recall → cloud variant question (--dry-cloud previews the prompt)
python scripts/pre_drill.py --index demo-vault/30-知识/.index --topic deadlock banker --qwen   # pre-exam drill sheet
```

### Study toolchain

```bash
python scripts/study_report.py --queue demo-vault/30-知识/错题队列.json       # weekly report (mastery / hotspots / FSRS load)
python scripts/export_anki.py --queue demo-vault/30-知识/错题队列.json --out anki.csv  # Anki cards with FSRS fields
python scripts/study_dashboard.py --queue demo-vault/30-知识/错题队列.json --out dash.html  # static HTML dashboard
```

## Data & memory

Everything lives on your machine, in portable formats:

| Content | Location |
| --- | --- |
| Error queue | `demo-vault/30-知识/错题队列.json` (ReviewQueue Schema 1.1: cause status, FSRS stability/difficulty, retest history) |
| On-device vector index | `<corpus>/30-知识/.index/` (vectors + npz cache, plain local files) |
| Learning memory | your own Obsidian Vault (`00-系统 / 20-项目 / 30-知识 / 40-真题` layout convention) |
| Subject packs | `subjects/<subject>/profile.json` |

Vault integration is optional — the error queue is just a JSON file you own.

## Usage

### Where it runs

- **Codex / Codex CLI**: `python install.py --host codex`
- **Claude Code**: `python install.py --host claude-code` (into `~/.claude/skills/`)
- **Any other agent**: `--host generic --target <dir>`, then load the Markdown skills the way your agent expects.

### Memory control

- Without a Vault: all state is the error-queue JSON; delete it and there is nothing else.
- With a Vault: skills write only into the paths declared in the subject config — never elsewhere.
- Uninstall: `--uninstall` removes exactly what the install manifest lists; learning data is untouched.

### Common prompts

After installing, just talk to your agent:

| Scenario | Example prompt |
| --- | --- |
| Log a mistake | "Add this question to my error queue; my cause hypothesis is …" |
| Cluster & schedule | "Cluster similar error causes in my OS questions and schedule retests with FSRS" |
| Today's reviews | "Which questions should I re-test today, with retrievability?" |
| Plan | "Back-plan 8 weeks to my exam on Dec 21 and expand this week into timeboxes" |
| Review a question | "Point out only my first mistake — don't give the answer yet" |
| Variant drill | "Give me a variant question targeting the confirmed cause of r028" |
| Pre-exam drill | "Tomorrow is my OS exam — build a drill sheet on deadlock & banker's algorithm" |
| Mock exam | "Run a frozen-paper mock exam; no hints until I submit" |
| Diagnose | "Diagnose my last two weeks: deviations, risks, adjustments" |
| Semantic search | "Which of my past mistakes is closest to 'page-fault handling'?" |
| Report / Anki | "Generate this week's study report" · "Export my error queue to Anki cards" |
| New subject | "I'm preparing for the law exam — generate a subject pack" |

## Architecture

Three layers: host adapters (`adapters/`, `install.py`) → universal Skills core (`plugins/study-copilot/`: 15 skills + 23 contracts) → subject packs (`subjects/`), with local retrieval (`scripts/local_retrieval/`). Details: [ARCHITECTURE.md](ARCHITECTURE.md).

## Quick start

```bash
git clone https://github.com/yq6666-66/study-copilot-skills.git
cd study-copilot-skills

python install.py --list                  # see what will be installed
python install.py --host auto --dry-run   # preview, writes nothing
python install.py --host claude-code      # install (Codex users: --host codex)

python scripts/validate_records.py        # validate data assets (Schema 1.1 + subject packs)

# then ask your agent: "Which questions should I re-test today?"
```

Cloud coaching is optional and works with any OpenAI-compatible provider (OpenAI, DeepSeek, Kimi, SiliconFlow, local Ollama / vLLM, …). Credentials live only in your local environment variables — this repo never stores secrets:

1. **Collect three values** from your provider's console: the compatible Base URL, a model name, and an API key.
2. **Set three environment variables**:

   ```powershell
   # Windows (PowerShell) — reopen the terminal afterwards
   setx OPENAI_BASE_URL "<provider endpoint, e.g. https://api.deepseek.com/v1>"
   setx OPENAI_MODEL "<model name>"
   setx OPENAI_API_KEY "<your API key>"
   ```

   ```bash
   # macOS / Linux (add to ~/.zshrc or ~/.bashrc to persist)
   export OPENAI_BASE_URL="<provider endpoint>"
   export OPENAI_MODEL="<model name>"
   export OPENAI_API_KEY="<your API key>"
   ```

3. **Verify**: `python scripts/demo_pipeline.py --item r028` runs the full edge-recall → cloud variant-question chain (add `--dry-cloud` for an offline preview first).

Without configuration, every feature stays fully offline.
