# AI 技术实践说明

> 对应比赛要求「AI 实践需真实可验证」与「端云协同可获技术加分」。本文按**实际使用范围如实描述**，所有数字与佐证可在仓库、`logs/qwen/` 留痕与 DashScope 控制台交叉核对。

## 一、技术栈演进总览（前作 → 本作）

本项目是前作 **408考研插件（kaoyan-408 v2.4.0，已开源）** 的通用化演进，技术栈一脉相承并完成三层升级：

| | 前作 408考研插件 v2.4.0 | 本作 学习副驾 v1.13 |
| --- | --- | --- |
| 定位 | 408/考研单领域学习插件 | **任何 Agent × 任何科目**的通用学习认知引擎 |
| 宿主 | Codex 单宿主 | Codex / Claude Code / 通用（多宿主适配 + 清单化安装卸载） |
| 推理 | 100% 宿主云端模型 | 宿主模型 + **云端 Qwen（DashScope）** + **端侧本地推理** |
| 记忆 | Obsidian Vault（JSON Schema 1.0/1.1） | 同左 + **端侧向量索引**（语义召回） |
| 科目 | 固定五科（数学/英语/408/政治） | **配置驱动**（考研预置 + 法考/注会/任意科目向导） |
| 质量工程 | pytest + semgrep + 可复现发布 | **六道 CI 门禁 × Python 3.10-3.12 矩阵**（97 tests / Schema / 文档路径 / semgrep / 契约覆盖 / 数字一致性） |
| 留痕 | 无独立调用留痕 | **36 次 Qwen 调用全留痕**（消息/回复/usage/时延 + 防泄漏断言 + 聚合审计） |

**继承自前作并保留的技术**：Skills-only 架构（无后台服务）、行为契约模式（Markdown 契约 + JSON Schema 严格校验）、Obsidian Vault 本地记忆、证据与版权约束（原创标注/分级引用）、Python 校验与发布工具链、MIT 开源。

**本作新增**：端侧本地推理（embedding/向量缓存/增量索引）、云端 Qwen 专项通道（留痕/防泄漏/降级矩阵）、多宿主适配层、科目配置驱动、FSRS 调度、六道 CI 门禁、Mimosa 深度安全扫描。

**Qwen 真实调用统计（截至 2026-09-14）**：本作品代码链路——**共 36 次真实调用全部留痕，累计 81,379 tokens**（qwen-flash ×30 + qwen3.8-flash ×6），逐条 JSON 见 `logs/qwen/`，聚合审计 `python scripts/qwen_engine.py --stats`。

## 二、端云协同（核心架构 · 技术加分项）

学习副驾把每一次「错题陪练」完整拆解为端云两段协同，两端能力对等、互为降级。

### 2.1 端侧承担的能力（本地 AI PC，数据不出域）

1. **语义向量索引**：`embed_index.py` 在本地 CPU 运行 bge-small-zh-v1.5（ONNX），把错题队列（ReviewQueue 1.1）与 Vault 笔记编码为 512 维向量索引（实测 53 篇 / 2.3s；2000 条基准 7.2s）。
2. **语义召回**：`semantic_search.py` 对新错题毫秒级召回相似历史错题与笔记（实测死锁查询 Top3 全中、跨科目零串扰；2000 条规模查询 avg 15.4ms / p95 28.8ms）。
3. **向量缓存与增量**：`vec_cache.py` npz 二进制缓存 + `--incremental` 增量复用——2000 条改 1% 仅需 0.39s（vs 全量 7.31s，**19×**）。
4. **FSRS 间隔复习调度**：`scheduler.py` 实现开源 FSRS 核心公式（遗忘曲线 R=(1+19t/81S)^-0.5、初始稳定性 S0=w[评分-1]、难度均值回归阻尼、期望保持率反解间隔），40 条错题全自动排期。
5. **数据边界**：索引、缓存、学习记忆全部存于本地 `.index/` 与用户 Vault，任何环节不上传学习数据。

### 2.2 云端承担的能力（DashScope Qwen）

1. **定向变式出题**：基于端侧召回的错题簇与 confirmed 错因，生成原创变式题与二次精讲（提示词硬约束：只基于给定错因、不复制原题面）。
2. **科目配置生成**：法考/注会两份 `profile.json` 由 Qwen 生成并通过校验入库——新增科目机制层零改动的实证。
3. **内容与分析**：错因聚类报告、周报洞察、仪表盘执行摘要、Anki 卡片措辞、英文 README 初稿等（六类链路明细见第三节）。

### 2.3 协同方式（三步闭环）

```
一条命令（demo_pipeline.py / pre_drill.py）
① 端侧召回：本地索引毫秒级返回相似错题簇（带相似度分数）
② 最小交接：仅学科文本（知识点+错因描述）组织为 prompt，--dry-run 隐私预览
③ 云端生成：Qwen 产出变式题/精讲 → 自动留痕 logs/qwen/ → 回写本地记忆层
```

**降级矩阵**：

| 场景 | 行为 |
| --- | --- |
| 端侧未就绪 | 跳过检索，直接基于会话与 Vault 学习 |
| 云端无 Key/超时 | 会话内出题并明示「本次未使用 Qwen」 |
| 两端均受限 | 返回可解释的本地结果，不伪造任何生成标注 |

### 2.4 可核验性

- 端侧：`bench.py` 性能基准（合成数据固定种子可复现）+ 检索输出样例。
- 云端：`logs/qwen/` 逐条 JSON（消息/回复/usage/时延）+ `--stats` 聚合 + 平台控制台用量截图交叉核对。
- 工程面：GitHub Actions 运行记录公开可查（六道门禁 × 三版本矩阵连续绿）。

## 四、Qwen 专项链路（对齐特别赛题）

Qwen 在作品中承担六类**真实发生**的链路，全部经 DashScope 接口调用并留痕：

1. **错题陪练（双科目）**：基于 confirmed 错因生成原创变式题与二次精讲（408 LRU/FIFO、数学一级数双错因等）。
2. **科目配置生成**：法考/注会两份 `profile.json` 由 Qwen 生成并通过校验入库——新增科目机制层零改动的实证。
3. **跨科目内容生产**：demo-vault 原创练习集 01/02（数学+408）、英语一写作练习、政治背诵卡片。
4. **数据分析**：错因聚类报告（40 条队列优先簇）、错题复测周报、卷种差异对比。
5. **工程辅助**：代码审查×3（其一为 Qwen 对自身引擎源码的审查）、接入教程、FAQ、英文 README 初稿、ARCHITECTURE 初稿。
6. **认知增强定位**：把用户的错误模式变成可复测的原创变式题、把考试大纲变成可执行配置——这正是特别赛题「基于 Qwen 大模型的认知增强」的对齐点。

- 调用纪律：先 `--dry-run` 预览请求体，确认无个人信息后真实调用；默认低成本模型 qwen-flash。
